## 1. 技能概述

### 1.1 基本信息

| 属性 | 值 |
|------|-----|
| 名称 | `/spec` |
| 命令 | `helix spec "<需求描述>"` |
| 分类 | Execution (执行引擎) |
| 状态 | DRAFT (设计中) |
| 依赖 | 无 |

### 1.2 核心职责

将用户的自然语言需求描述转化为结构化的规格说明书（Spec），为后续的 `/build`、`/verify` 等技能提供清晰的输入。

### 1.3 输入输出

```
输入: "我想做一个用户登录功能"
输出: 结构化规格说明书 (Markdown 格式)
```

## 3. 意图解析

### 3.1 需求分类

用户输入的需求可以分为以下类型：

| 类型 | 关键词 | 示例 |
|------|--------|------|
| CRUD | 创建, 添加, 删除, 修改, 管理 | "做一个用户管理系统" |
| API | 接口, 服务, REST, GraphQL | "做一个用户 API" |
| 算法 | 计算, 排序, 搜索, 优化 | "实现一个推荐算法" |
| 集成 | 对接, 集成, 第三方 | "集成 Stripe 支付" |
| 页面 | 页面, 组件, UI, 前端 | "做一个登录页面" |
| 脚本 | 脚本, 工具, 命令行 | "做一个数据导入脚本" |
| 基础设施 | 部署, CI/CD, 配置 | "配置 CI/CD" |

### 3.2 实体提取

从需求中提取关键实体：

```python
@dataclass
class ExtractedEntities:
    domain: str = ""        # 领域：用户、订单、支付...
    action: str = ""        # 动作：登录、查询、创建...
    entities: List[str] = [] # 涉及的实体：用户名、密码、验证码...
    integrations: List[str] = [] # 第三方集成
    constraints: List[str] = []  # 约束条件
```

## 4. Socratic 提问机制

### 4.1 触发条件

当以下任一条件满足时，触发 Socratic 提问：

1. **领域不明确** — "做一个管理系统" → "什么类型的管理系统？"
2. **动作不明确** → "做一个功能" → "具体是什么功能？"
3. **用户不明确** → "给用户使用" → "目标用户是谁？"
4. **价值不明确** → "做一个登录" → "登录后用户能做什么？"

### 4.2 提问策略

```
需求清晰度 = f(领域明确, 动作明确, 用户明确, 价值明确)

if 需求清晰度 >= 0.8:
    直接进入模板填充
elif 需求清晰度 >= 0.5:
    选择性提问（最多 3 个关键问题）
else:
    引导式提问（直到清晰度 >= 0.7）
```

### 4.3 预设问题库

| 缺失信息 | 提问模板 |
|----------|----------|
| 领域 | "请问这个功能属于什么业务领域？" |
| 用户 | "请描述一下目标用户是谁？" |
| 价值 | "这个功能为用户解决什么问题？" |
| 规模 | "预计有多少用户会使用这个功能？" |
| 集成 | "需要与哪些第三方系统对接？" |
| 平台 | "需要支持哪些平台（Web/iOS/Android）？" |
| 验收 | "你如何判断这个功能做完了？" |

## 6. 人类确认

### 6.1 确认节点

```
用户输入 → 意图解析 ─┐
                    ▼
              需求澄清 (可选)
                    │
                    ▼
              选择模板 ─┐
                    ▼
              填充 Spec
                    │
                    ▼
              展示给用户 ───────► 确认 / 修改 / 取消
                    │
                    ▼
              完成
```

### 6.2 确认选项

| 选项 | 动作 |
|------|------|
| 确认 (Y) | 保存 Spec，继续下一步 |
| 修改 (M) | 编辑特定章节 |
| 取消 (C) | 终止，保留草稿 |

### 6.3 修改模式

用户可以指定修改范围：
- `spec edit section:<章节名>` — 修改特定章节
- `spec edit item:<编号>` — 修改特定需求点
- `spec edit` — 打开完整编辑器

## 7. CLI 接口设计

```bash
# 基本用法
helix spec "我想做一个用户登录功能"

# 带选项
helix spec "我想做一个用户登录功能" \
  --template crud \           # 指定模板
  --no-confirm \              # 跳过确认
  --output spec.md \          # 输出文件
  --context .                 # 项目上下文

# 交互模式
helix spec                    # 进入交互式提问

# 查看模板
helix spec templates          # 列出所有模板

# 验证 Spec
helix spec validate spec.md   # 验证规格说明书
```

## 8. 配置文件

### 8.1 项目级配置 `.helix/spec.yaml`

```yaml
spec:
  # 默认模板
  default_template: crud

  # 自动确认模式
  auto_confirm: false

  # 模板路径
  template_dir: .helix/templates

  # Socratic 提问策略
  socratic:
    max_questions: 5
    confidence_threshold: 0.7
```

### 8.2 全局配置 `~/.helix/config.yaml`

```yaml
spec:
  # 首选 AI 引擎
  engine: claude_code

  # 输出格式
  default_format: markdown

  # 自动学习
  learn_from_history: true
```
